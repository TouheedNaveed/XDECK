How to Properly Open Specific Chrome / Browser Profiles on XDECK

When setting up browser profiles on Windows, always wrap file paths containing spaces in double quotes "...". In XDECK, use the Start App action kind:

✅ WINDOWS (Start App):
Path: "C:\Program Files\Google\Chrome\Application\chrome.exe"
Args: --profile-directory="Profile 1"
🍎 macOS & 🐧 Linux:
Mac (Run Command): open -na "Google Chrome" --args --profile-directory="Profile 1"
Linux (Start App): google-chrome | Args: --profile-directory="Profile 1"

How to find your Profile directory name: Open Chrome → Navigate to chrome://version → Look at Profile Path (e.g., Default, Profile 1, Profile 2).

FAQ & TROUBLESHOOTING

Frequently Asked Questions

Why did my button show a red dot or "Trigger Failed" even though the app opened?

In older versions or when using Open App, XDECK waited for the application process to terminate before sending a response. If an application (like Chrome or VS Code) remained open for more than 5 seconds, your phone hit a response timeout and displayed a red indicator. In XDECK v1.4.1+, Start App and Open App acknowledge triggers immediately, ensuring an instant green confirmation dot.

Why do paths with spaces fail if unquoted on Windows?

On Windows, paths like C:\Program Files\Google\Chrome\Application\chrome.exe have a space between "Program" and "Files". If passed without quotes, the Windows command interpreter sees C:\Program as the program name and fails with "command not recognized". Always wrap paths with spaces in double quotes: "C:\Program Files\...".

What is the difference between "Start App", "Open App", and "Run Command"?

  • Start App: Ideal for launching executables with custom command line arguments (e.g., launching Chrome with --profile-directory="Profile 1").
  • Open App: Quick launch for system-registered apps by name (e.g. spotify, notepad, calc).
  • Run Command: Runs any terminal/PowerShell script or command line tool directly with full shell capabilities.
